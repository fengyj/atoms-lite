# Atoms.dev 功能分析

## 1. 文档目的

本文总结 atoms.dev 的产品定位、用户主流程和核心能力，用于理解其面向交互式应用构建的产品形态。本文只包含产品能力分析，不包含 atoms-lite 的技术设计、开发计划或实现任务。

## 2. 产品定位

Atoms 是一个通过自然语言与智能体协作构建、验证和发布应用的产品。其核心价值不是单纯生成代码，而是围绕以下闭环提供持续、可控的交付体验：

> 描述需求 → 智能体执行 → 预览验证 → 迭代修改 → 发布与更新

从产品结构看，它同时覆盖：

- 对话式需求输入
- 多智能体分工与协作
- 应用生成和代码修改
- 预览、测试和可视化调整
- 项目版本与历史
- 后端能力与数据管理
- 发布、分享和持续更新
- 分析、增长及外部服务集成

## 3. 主流程

### 3.1 创建和描述

用户从一个需求开始，可以通过自然语言、附件或其他上下文说明想要构建的应用。对话不仅用于首次生成，也贯穿后续修改、纠错和功能扩展。

聊天输入支持多种交互要素，例如文本、附件、模式选择、角色模式、语音和发送控制。

### 3.2 智能体执行

需求进入系统后，由协调者理解目标、拆分工作并选择适当的专家角色。不同角色可以分别负责：

- 需求与产品规划
- 研究与资料整理
- 前端和后端开发
- 数据建模
- 测试与问题修复
- SEO、广告和增长

系统在执行过程中可以输出进度、阶段结果、工具调用和需要用户确认的问题。

### 3.3 预览和验证

生成结果可以在产品内直接预览。预览不仅用于观察静态页面，还应支持用户操作应用、查看不同页面、切换设备尺寸，并检查运行状态和错误。

对于开发相关工作，预览通常还伴随代码文件、执行日志、构建状态和控制台输出。

### 3.4 迭代修改

用户可基于当前预览继续提出修改意见，例如：

- 调整页面结构
- 增加表单或列表
- 改动视觉样式
- 增加数据处理
- 修复运行错误
- 恢复某个历史版本

智能体应理解“基于现状修改”，而不是每次都重新生成整个项目。

### 3.5 发布和更新

生成和预览并不等同于线上发布。发布通常是一个独立动作，生成可访问的线上地址或将指定版本推送到现有站点。

后续修改则需要继续通过更新操作部署，用户可以区分草稿、预览版本与线上版本。

## 4. 对话与多智能体

### 4.1 对话会话

会话是项目工作的核心上下文，通常保存：

- 用户需求
- 智能体回复
- 工具调用过程
- 用户补充信息
- 执行结果和错误
- 对应的版本或产物

用户可以重新打开会话并继续工作，而不需要重新描述全部背景。

### 4.2 多角色协作

平台可以将工作分给具有不同职责的智能体，例如：

- 协调者：理解目标并组织执行
- 产品角色：梳理需求和用户流程
- 工程角色：实现应用和数据逻辑
- 研究角色：补充外部信息
- 增长角色：处理 SEO、广告或分析配置
- 测试角色：验证结果并发现问题

用户看到的不只是最终回答，还包括各角色的阶段性贡献和当前工作状态。

### 4.3 任务队列和运行控制

在智能体仍在执行时，用户可能继续添加需求。平台可将后续请求加入队列，并支持：

- 排队
- 编辑
- 删除
- 调整顺序
- 停止当前运行
- 在错误后恢复
- 提交反馈

## 5. 项目、版本和历史

### 5.1 项目组织

一个项目包含应用产物以及与之相关的上下文，例如：

- 会话
- 代码和文件
- 数据
- 版本
- 发布记录
- 共享设置
- 外部连接器
- 使用统计

### 5.2 版本

版本用于记录应用在某个阶段的稳定快照。典型能力包括：

- 查看版本列表
- 切换历史版本
- 对比不同版本
- 回退到旧版本
- 基于历史版本克隆或创建分支

版本将运行结果与某次对话、工具执行和文件变更建立关联，使生成过程可追溯。

### 5.3 代码与文件

用户可以查看项目文件结构、搜索内容、打开代码、下载项目，或对单次会话产生的修改进行提交和丢弃。

## 6. 预览和可视化编辑

### 6.1 预览模式

预览通常支持：

- 桌面和移动视图
- 页面切换
- 新标签页打开
- 刷新
- 运行日志或控制台
- 显示构建和运行错误

### 6.2 可视化元素编辑

用户可在页面中选中元素，并针对内容或样式发出修改指令。常见操作包括：

- 修改文案
- 调整间距、颜色和尺寸
- 改变布局
- 添加或删除元素
- 将多个调整一次性发送给智能体

局部视觉调整需要与应用的全局主题或设计约束协调。

## 7. 主题与设计

主题系统把项目级的视觉决策集中管理，例如：

- 主色和辅助色
- 字体
- 圆角
- 阴影
- 交互动效
- 背景与材质

全局主题与页面元素的局部修改需要同时存在。局部修改不应破坏整体主题，主题调整也需要可控地应用到已有页面。

## 8. 后端和数据能力

Atoms 将数据库、应用用户、密钥、文件存储、AI、邮件和定时任务等能力组织为应用的云端功能。

### 8.1 数据库

数据库支持应用保存结构化数据，并区分开发和生产环境。常见数据操作包括建表、迁移、查询、修改和数据检查。

### 8.2 应用用户

应用用户是由生成应用服务的终端用户，不等同于工作区协作者或项目成员。应用用户能力可能包括注册、登录、权限和用户数据隔离。

### 8.3 密钥与配置

第三方服务密钥和敏感配置需要通过专门的配置系统管理，避免直接进入聊天内容、生成代码或公开文件。

### 8.4 文件存储

应用可以保存和读取上传文件、图片等非结构化数据，通常需要区分公共资源和受权限控制的资源。

### 8.5 AI、邮件和定时任务

平台还可以为生成应用提供：

- AI 模型调用和用量统计
- 邮件模板、发送和状态日志
- 定时或延迟任务
- 后台作业

## 9. 发布与分发

### 9.1 发布状态

项目至少应区分：

- 开发草稿
- 可预览版本
- 已发布版本

预览过程中的修改不应自动影响线上应用。

### 9.2 域名与访问

发布能力可覆盖：

- 平台默认访问地址
- 自定义域名
- DNS 和证书状态
- 公开或受限访问
- 分享链接

### 9.3 导出和复制

除在线部署外，项目还可以通过源码压缩包、项目复制或分支等方式进行迁移和复用。

## 10. 连接器

连接器用于让应用或智能体访问外部服务，例如：

- GitHub
- Supabase
- Google Analytics
- Google Search Console
- Google Ads

连接器通常涉及 OAuth、权限范围、连接状态、断开连接和错误恢复。外部连接器及平台内置云服务之间也可能存在互斥或边界限制，不能把它们当作可以同时随意启用的普通插件。

## 11. 分析与增长

除应用构建外，Atoms 还包含面向发布后运营的能力：

- 流量和事件分析
- SEO 内容与站点检查
- 搜索表现观察
- 广告投放辅助
- 指标分析和优化建议

这部分能力通常依赖对应的数据连接器和应用已发布或已接入真实流量。

## 12. 综合产品特征

Atoms 的主要产品特征可以归纳为：

1. 对话是主要工作界面。
2. 智能体不仅回答问题，还通过工具改变项目。
3. 生成结果必须可以运行、预览和验证。
4. 修改过程可持续，历史与版本可追溯。
5. 预览、发布和更新是不同状态。
6. 数据、存储、密钥和后台服务属于应用运行的一部分。
7. 发布后仍可进入分析、增长和持续优化流程。
